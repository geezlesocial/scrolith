# Scrolith User and Admin Handbook

## 1. Purpose

This handbook explains how Scrolith is used from two perspectives:

- end users
- platform administrators

It is based on the currently visible structure of the platform in the codebase and is intended as an operating guide.

## 2. Who Scrolith Serves

Scrolith supports multiple user types:

- guests
- signed-in members
- freelancers
- employers or clients
- creators and live hosts
- admins
- moderators and staff
- developers

Each role uses different areas of the platform, but all operate inside the same ecosystem.

## 8. Recommended Admin Operating Workflow

### Daily workflow

1. Review Overview for platform state
2. Check Messages and Support modules
3. Review moderation, disputes, and community surfaces
4. Review live and sensitive content areas
5. Monitor finance, payouts, and monetization status
6. Validate homepage and campaign surfaces

### Weekly workflow

1. Review market intelligence and insights
2. Review user growth and engagement trends
3. Audit homepage and guest experience settings
4. Review ads, monetization, and payment configurations
5. Review file storage and content workflows

## 10. Platform Behavior Across Devices

Scrolith is designed to work across:

- desktop web
- mobile web
- Android app
- iOS-ready mobile shell

Because the mobile app is based on the same frontend build, users should experience a largely shared product model across devices, with native enhancements where plugins are used.

## 11. Best Practices for Teams Using Scrolith

For product teams:

- treat Scrolith as one connected ecosystem
- manage homepage, live, and community systems together
- keep operator controls aligned with policy

For admins:

- use the dashboard as the first operational surface
- avoid using code changes for settings that already exist in admin
- review live, monetization, and content controls together

For support and moderation teams:

- use message, dispute, moderation, and support modules as a connected workflow
- monitor social, marketplace, and live behaviors as one user journey

## 12. Final Handbook Summary

Scrolith is designed for two simultaneous realities:

- users need a platform to build presence, engage, find work, and monetize activity
- operators need a platform they can govern and tune in real time

That dual design is visible across the product:

- rich user-facing experiences
- broad admin-facing control
- shared web/mobile delivery
- integrated social, commerce, creator, and AI systems

That is the operating model teams should use when working with Scrolith.
